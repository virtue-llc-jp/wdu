# アーキテクチャ

## 目的

`wdu` は、ファイルシステムの更新を常時監視し、ディレクトリごとの現在使用量と、
観測開始からの増減累計を更新します。CLI は指定ディレクトリの集約行を読み取り、
その配下全体の累計を返します。

ファイルシステムイベント自体は使用量の差分ではありません。イベントを受け取った
時点で対象ディレクトリの状態を再計算し、前回値との差を対象ディレクトリと全祖先の
集約行へ反映することが基本方針です。差分自体をイベント単位で永続化しません。

## crate の責務

### `wdu-core`

プラットフォーム非依存の共有データモデルを持ちます。

- `FileChange`: ファイルシステムイベントの正規化表現
- `FileChangeKind`: 作成、変更、削除、その他
- `DirectorySnapshot`: 再帰スキャンで得た配下全体の論理使用量
- `DirectoryUsageAggregate`: 配下全体の現在使用量と観測開始からの累計

ここには FSEvents、SQLite、CLI 引数などの OS・入出力固有の処理を置きません。

### `wdu-daemon`

常駐プロセスの入口です。macOS では `notify` の FSEvents バックエンドを使い、
指定ディレクトリを再帰的に監視します。

現在の処理は次の範囲です。

1. 監視対象を canonical path に解決する。
2. SQLite を開き、監視対象配下を初回スキャンして集約行を初期化する。
3. ファイルシステムイベントを受信する。
4. 100ms の短い batch 窓で同一パスのイベントをまとめ、影響を受ける最上位の
   ディレクトリを再計算して対象と祖先の集約行を更新する。
5. イベント種別とパスを `FileChange` として開発用 NDJSON に出力する。
6. 起動時と設定された間隔で、保持期間より古い hourly bucket を日次へ圧縮する。

イベント受信、使用量の再計算、永続化は別モジュールの責務として分離します。

### 永続化層

`wdu-storage` は SQLite adapter を `wdu-core` から分離します。ディレクトリごとの集約行を持ち、
親の行にも子孫を含む累計を保持します。指定ディレクトリの集計は子孫走査ではなく、
パスの主キー検索 1 回で完了します。

差分が発生した場合は `directory_usage_bucket` にも対象と全祖先の hourly 値を記録し、
daemon の定期処理で古い履歴を日次へ統合します。

### `wdu-config` と `wdu-usage`

`wdu-config` は TOML 設定、Homebrew の `etc/wdu/config.toml`、環境変数、CLI 引数の
共有設定を扱います。`wdu-usage` は論理サイズの再帰スキャンと symlink を辿らない
方針を提供し、daemon と CLI の `record` が同じ測定処理を使います。

### `wdu-cli`

バイナリ名 `wdu` の CLI です。現在は `query` と `record` サブコマンド、ディレクトリ・
SQLite・config パス引数を持ち、集約行または時間範囲の差分を JSON で出力します。
クエリ処理では、CLI の引数解釈とストレージアクセスを分離し、出力形式を
ストレージの内部形式に依存させないようにします。

## イベントから累計までの流れ

```text
初回スキャン ─────────────┐
                          ▼
FSEvents → FileChange → 対象ディレクトリを再計算
                          │
                          ▼
             対象と全祖先の集約行を更新
                          │
                          ▼
                       wdu query
```

## 採用する設計上の制約

- 変更イベントは 100ms の batch 窓でまとめ、同じ影響範囲を一度だけ再計算する
- rename は旧パスを tombstone、新パスを新規行として再同期する。削除も行を残す
- シンボリックリンクは二重計上を避けるため辿らない
- 使用量は通常ファイルの論理サイズを合計する。割り当てブロックサイズは別仕様とする
- SQLite DB は監視 root の外側に置き、DB 自身の更新を監視イベントにしない
- 保存先とスキーマのバージョニング。SQLite の `PRAGMA user_version` を使う
- 常駐プロセスの起動方法（手動、`launchd` など）

任意の event 履歴は保存しません。時間範囲 query のために差分を hourly bucket へ
集約し、古い bucket は日次へ圧縮します。

`FileChange` は現在も使用量差分ではなく、再計算を起動するための通知としてだけ
扱います。
